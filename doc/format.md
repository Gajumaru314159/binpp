# 構造体定義ファイルの解析とバイナリ読み取りフロー

`specification.md` に記載された仕様を踏まえ、構造体ファイルを読み込んでバイナリを解釈するまでの工程を整理する。ここでは字句解析の実装方針を含めた具体的な技術スタックについても示す。

## 1. 構造体定義ファイルのロード
1. **ファイル探索**
   - `settings.json` または `binpp.json` の `includePaths` に記載されたディレクトリから `.h` ファイルを検索する。
   - `ファイル名.h` と同名の拡張子を持つバイナリに自動的に適用する仕組みとする。
2. **ファイル形式**
   - C++ のサブセットで記述されたテキストファイル。`struct` と `enum` を基本要素として使用する。
   - 配列長を表す式や `parent.member` 形式の親スコープ参照を記述可能。

## 2. パース処理
1. **字句解析**
   - [Chevrotain](https://github.com/SAP/chevrotain) を用いて TypeScript 上でトークナイザを構築する。
   - キーワード（`struct` `enum` など）、識別子、数値リテラル、演算子、括弧、コメントをトークン化する。
2. **構文解析**
   - Chevrotain のパーサ機能で AST を生成し、構造体・列挙型・メンバを表現するノードを構築する。
   - 配列長式は AST ノードとして保持し、後段で評価できるようにする。
3. **型登録**
   - 解析結果を型テーブルに登録し、`struct Root` をエントリポイントとして保持する。

## 3. 式評価
- バイナリ読み取り時に配列長式や `parent.member` 参照を評価する。
- 演算子は `+`、`-`、`*`、`/` をサポートし、括弧による優先度制御が可能。
- 配列ループ時には `$i`, `$j` などの特殊変数で現在のインデックスを参照する。

## 4. バイナリ読み取りフロー
1. **ファイルオープン**
   - 対象バイナリを `DataView` もしくは `Buffer` として取得する。
2. **ルート構造体から開始**
   - `Root` のメンバを定義順に読み取り、必要に応じて配列長式を評価する。
3. **スコープスタック管理**
   - 構造体に入るたびスタックにスコープを積み、読み取った値を保存する。
   - `$i` 等のインデックス変数はスコープ毎に管理する。
   - `parent.member` が使用された場合はスタックを遡って値を取得する。
4. **オフセット更新**
   - 各フィールドのサイズ分だけバイトオフセットを進めて次のデータを処理する。
5. **結果保持**
   - 読み取った値はツリービュー表示用のデータ構造として保持し、VS Code 側に送信する。

## 5. エラーハンドリング
- 未定義シンボルの参照や式評価失敗時にはエラーを出力し、処理を中断する。
- 配列長式は、それ以前に読み取った値のみを参照できるよう静的にチェックする。

## 6. 例: `Root` 構造体
```cpp
struct Root {
  Header header;
  char data[header.dataSize];
  Footer footer;
};
```
1. `Header` を読み取り `dataSize` を記録する。
2. `data[header.dataSize]` をその値で評価して取得する。
3. 続けて `Footer` を解析し、全体のデータを完成させる。

以上が構造体定義ファイルを用いたバイナリ読み取り処理の設計である。
